# Publishing SPino on Google Play

Current release: [SPino 6.1.0 submission pack](submission-6.1.0.md). The signed bundle and assets are prepared locally; upload and rollout remain separate owner actions.

The sections below also retain initial account setup instructions.

| File | Contents |
|---|---|
| [listing.md](listing.md) | Store listing texts (es-ES default, en-US), release notes, category, asset list |
| [play-console-forms.md](play-console-forms.md) | Answers for App content: data safety, content rating, audience, ads, permissions |
| [privacy-policy.html](privacy-policy.html) | Bilingual privacy policy page to host at a public URL |
| `screenshots/<lang>/<device>/` | Phone, 7" and 10" tablet screenshots in Spanish and English |
| `assets/brand/play-store-icon-512.png`, `assets/brand/play-store-feature-1024x500.png` | Icon and feature graphic |

## 1. Before you start

* **Developer account**: <https://play.google.com/console> (one-time USD 25 fee, identity verification).
* **Personal accounts created after 13 November 2023** must run a **closed test with at least 12 testers for
  14 consecutive days** before they can apply for production. Organisation accounts are exempt; they need a
  D-U-N-S number.
* **Application ID is permanent**: `com.miguecoll.spino`. Once uploaded it can never change. Rename it now
  in `android/app/build.gradle` and `capacitor.config.json` if a different ID is wanted (for example
  `com.spino.piano`); the installed debug builds would then be a separate app.
* **Support email**: `support@spinoapp.com` (privacy policy, website and Play Console contact).
* **Check the name**: search Play and trademark registers for "SPino" before publishing.

## 2. Publish the website (privacy policy + app page)

The public site lives in `site/` and is generated by `node scripts/site/build-site.mjs`: landing page in
Spanish at `/`, English at `/en/`, the bilingual privacy policy at `/privacy/`, and screenshots taken from
`docs/play-store/screenshots`. The support contact is `support@spinoapp.com`.

It is hosted on **Cloudflare Workers Builds** (free, works with the private repository, publishes only `site/`):

1. <https://dash.cloudflare.com> → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
2. Authorise GitHub for `cuoyot/spino` only, then select the repository and branch `master`.
3. Project name `spino` (gives `https://spino.pages.dev` if free); framework preset **None**; build command
   empty; build output directory `site`.
4. **Save and Deploy**. Every push to `master` republishes the site.
5. Optional: **Custom domains** to add your own domain later.

Use `https://<project>.pages.dev/privacy/` as the Play Console privacy policy URL and
`https://<project>.pages.dev/` as the website. After UI changes: regenerate the screenshots, run
`node scripts/site/build-site.mjs`, commit and push.

### Search and answer-engine metadata

`scripts/site/seo.mjs` is the source of truth for the production origin (`https://spinoapp.com`),
canonical URLs, language alternates, JSON-LD, `robots.txt` and `sitemap.xml`. The sitemap contains
the three SPino landing pages, three Arcade pages and the two privacy pages. Spanish is the
`x-default` destination for each translated group. Do not add downloads, fragments, preview hosts
or a build-time `lastmod` to the sitemap.

The English, Spanish and Catalan product descriptions and FAQ answers live in `site-copy.mjs`.
The visible FAQ and `FAQPage` JSON-LD use the same content. `WebSite`, `WebPage` and
`SoftwareApplication` describe the actual app; stable download metadata shares `STABLE_RELEASE`
with the visible download card. Keep Google Play, stable and beta versions distinct. Do not invent
ratings or reviews to satisfy rich-result validators.

Public crawling is allowed, including search and answer-engine crawlers. Downloads receive
`X-Robots-Tag: noindex` from both static headers and the download Worker; do not disallow their
crawl in robots.txt because crawlers must be able to read this header. Images and demonstration
video remain crawlable. Cloudflare may prepend managed content-signal text to robots.txt, so
verify the served file and any account-level bot controls after deployment.

Regenerate and validate:

```sh
node scripts/site/build-site.mjs
node --test tests/site.test.js tests/site-seo.test.js tests/site-download.test.js
BROWSER_PATH="/path/to/chromium" node --test tests/site.browser.test.js tests/site-seo.browser.test.js tests/site-release-notes.browser.test.js
```

The browser suite requires Node with global WebSocket support; Node 20 can use
`--experimental-websocket`. Set `SPINO_SITE_SEO_EVIDENCE` to a **new** dated directory to save
responsive browser captures without replacing previous evidence.

After publication, confirm HTTP 200 for the eight sitemap destinations, correct content types for
robots.txt and sitemap.xml, matching canonical/hreflang URLs, JSON-LD in the returned HTML, and
a real 404 for missing pages. Submit `https://spinoapp.com/sitemap.xml` in the verified Google
Search Console and Bing Webmaster Tools properties when access is available. Deployment alone
does not submit the sitemap to those accounts or prove indexing.

References: [Google AI search guidance](https://developers.google.com/search/docs/appearance/ai-features),
[localized pages](https://developers.google.com/search/docs/specialty/international/localized-versions),
[SoftwareApplication](https://schema.org/SoftwareApplication), and [FAQPage](https://schema.org/FAQPage).
There is no special schema required for AI search. FAQ markup here documents real answers;
it does not promise a Google FAQ rich result or an AI citation.

## 3. Create the upload key (once)

Run it yourself in a terminal; it asks for a password that only you should know:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\create-upload-key.ps1
```

It creates `%USERPROFILE%\Android\spino-upload.jks` and `android/keystore.properties` (both ignored by git).
Back up the `.jks` file and the password in a password manager. In Play Console keep **Play App Signing**
enabled (default): Google holds the app signing key; this file is only the upload key.

## 4. Build the release bundle

1. Raise `versionCode` in `android/app/build.gradle` for every upload (29 → 30 …). Optionally set
   `versionName` to the public number you want to show (for example `1.0.0`).
2. Run the tests: `npm test`.
3. Build:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-release.ps1
```

The result is `SPino-<versionName>-<versionCode>.aab` in the repository root. Upload that file; Play no longer
accepts APKs for new apps. The debug `SPino.apk` from `scripts/build-apk.ps1` is only for sideloading.

## 5. Play Console, step by step

1. **Create app**: name *SPino: cuaderno de piano*, default language Spanish (Spain), App, Free, accept the
   declarations.
2. **Store listing** (*Grow → Store presence*): copy texts from [listing.md](listing.md), upload icon, feature
   graphic and the screenshots of each language (phone required; tablets recommended so the app is shown as
   tablet-ready). Add the English translation with its own screenshots.
3. **App content**: fill each declaration with [play-console-forms.md](play-console-forms.md).
4. **Testing → Closed testing**: create a track, add the testers' Google accounts (or a Google Group), upload
   the `.aab`, paste the release notes and roll out. Testers join from the opt-in link.
5. After 14 days with 12+ opted-in testers (personal accounts), **apply for production**, answer the short
   questionnaire about the test and, once approved, create the production release (start with a staged
   rollout, e.g. 20 %).
6. Countries: start with Spain and Spanish-speaking countries plus English-speaking ones; the UI supports
   Spanish, English and Catalan.

## 6. Pre-launch checks

* Install the signed build from the closed track on a phone and a tablet: first launch, Today, a piano
  session with the Hanon warm-up, MIDI over USB and Bluetooth, reminders after a restart, PDF import and a
  score download on Wi-Fi.
* Review the **Pre-launch report** in Play Console (automatic tests on real devices) and fix crashes or
  accessibility warnings it reports.
* Confirm the licence of every downloadable catalogue score (see *Content and copyright* in
  [play-console-forms.md](play-console-forms.md)).
* Target API: `targetSdkVersion 36` (`android/variables.gradle`) meets current Play requirements; Google raises
  the minimum every year (usually by 31 August).

## 7. Updating

In Claude Code, `/play-release [patch|minor|major|x.y.z]` runs these steps (`.claude/skills/play-release`).
For each update: raise the version with `node scripts/store/bump-version.mjs patch`, run `npm test`, rebuild screenshots if the UI changed
(`npm run build && node scripts/store/capture-play-screenshots.mjs es en`), check texts with
`node scripts/store/check-listing.mjs`, build with `scripts/build-release.ps1` and upload to the testing track
before promoting to production.
