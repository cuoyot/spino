# Native Android / iOS comparison — 2026-10-11

The owner requested native screenshots of every page and form on phone and tablet, in portrait and landscape, using the reviewed Android version as the reference. This review identifies differences for evaluation; it does not approve a redesign or implement product fixes.

The owner has now selected fixes and required iOS capabilities. See the [iOS implementation follow-up](platform-ios-followup.md) for current source changes, MIDI options, verification and remaining work. The observations below describe the preserved original comparison.

- [Eight-column comparison gallery](../../artifacts/platform-comparison/2026-10-11-native-01/index.html), with initial views and additional scroll frames.
- [Build, engine, fixture and device manifest](../../artifacts/platform-comparison/2026-10-11-native-01/manifest.json).
- [Surface coverage](platform-coverage.md), [scenario catalogue](../../artifacts/platform-comparison/2026-10-11-native-01/scenarios.json) and [measurements / coverage](../../artifacts/platform-comparison/2026-10-11-native-01/comparison-data.json).
- [Reusable native capture runner](../../scripts/review/native-platform-comparison.mjs), [gallery builder](../../scripts/review/build-platform-comparison.mjs), [evidence verifier](../../scripts/review/verify-platform-comparison.py) and [temporary iOS driver](../../scripts/review/platform-audit-ios.swift).

Android uses the published 5.2.7/code39 test APK. Its SHA-256 matches the reviewed release: `0359d74917a9b6041599feb3baf1d00aa1e057050b8b8cce6828b211a1a94a22`. The iOS comparison container uses all 255 identical web files extracted from that APK and the current iOS native integration. Its simulator-only driver operates the actual WKWebView and requests native rotation; it is not a shipping iOS release. Screenshots come from `adb screencap` and `simctl screenshot`, not browser device emulation.

All notebooks, PDF data, MusicXML material and cloud connection states are disposable synthetic fixtures. Cloud cases explicitly labelled “mock” intercept provider calls and do not access accounts or create provider files. Generated practice comparisons reuse saved note streams where indicated in the fixture metadata. Technical fixture identifiers, archive metadata and native cached-asset totals are excluded from layout findings. The native Android asset cache can retain earlier synthetic imports although the web notebook/asset stores are reseeded; for example, the background of Remove PDF can show two files on Android versus one on iOS. This is fixture history, not an asserted product parity defect. The opened record and confirmation content are shared. Ordinary native controls retain each test device's system locale; the app is Spanish. System clock labels are real; notebook dates and practice times are fixed.

The phone screens have matching physical resolution (1206 × 2622), and tablets use 1640 × 2360. OS chrome and safe areas differ, so equal physical resolution does not mean equal usable content height. Android runs API 34 with WebView **113.0.5672.136**; iOS runs an iOS 27 simulator. These engines are not equivalent in age. A legacy-engine PDF failure must not be interpreted as a general Android-versus-iOS layout failure.

The run evaluates 134 representative scenarios across eight device/orientation combinations (1072 states). The [final verification](../../artifacts/platform-comparison/2026-10-11-native-01/verification.json) records 2341 PNG frames, 1040 captured states and 32 blocked legacy-Android PDF states, with zero integrity/orientation errors. Every ordinary page and form has representative evidence; the acceptance gates below remain explicit.

For the corrected iPad landscape pass, the temporary container opts into full-screen mode (`UIRequiresFullScreen`) so native orientation requests take effect. This is an audit configuration, not a production project change. The simulator returns a portrait framebuffer containing rotated landscape content; the gallery normalizes it by a lossless 90° rotation and retains raw originals. Portrait iPad evidence includes the system window presentation.

## Coverage boundaries

The gallery records each attempted state and explicitly labels blocked states. A successful PNG capture is not functional acceptance: for example, a blank PDF canvas can still produce a valid image. Supplemental compatibility captures must be evaluated visually and remain separate from unmodified application behavior.

The scenario catalogue covers main navigation, empty/populated/pending Today, week/month calendars, planner, events, scheduling, manual logging, practice preparation, routines, active sessions, feedback, generated reading/technique/name/piano practice and settings, warm-up/scale guidance, archived learning, repertoire management, catalogue tabs and filters, downloaded MusicXML, part/rights/suitability/excerpt forms, PDF tools, progress/history, profile, local files, reminder settings, backup dialogs and retained reader settings.

Native create/open backup picker screenshots are included where labelled; they stop before saving or selecting a file. Remaining acceptance gates are photo/import picker subflows and provider return/cancellation/persisted-access behavior, connected cloud accounts and real two-device sync, hardware MIDI/Bluetooth/pedals, physical printing, screen readers/enlarged text, lifecycle interruptions, and the full set of network/storage failure permutations. These are not represented as verified merely because their parent form was captured. Browser baselines and earlier visual decisions remain unchanged; this audit adds native comparative evidence.

No product implementation, notebook migration, musical catalogue edit or release publication is authorized by this difference list. The next review step is to evaluate the findings and select fixes.

Environment observation: the first iPad command-readiness wait exceeded 45 seconds after simulator boot, then the app loaded normally ([diagnostic screenshot](../../artifacts/platform-comparison/2026-10-11-native-01/diagnostics/ipad-after-initial-readiness-timeout.png)). This is not a confirmed startup defect: cold-start timing needs an uninstrumented measurement under comparable host load.
