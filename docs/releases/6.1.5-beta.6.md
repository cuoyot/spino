# SPino 6.1.5-beta.6

Android versionCode 105. Fixes the setup/synchronization race, stale notebook names and recording MIME failures that also block complete ZIP export.

## Changes

- Setup waits for active synchronization, allows adoption behind its progress dialog and reserves the storage operation against automatic polling. Reservations release on close, success or failure.
- Verified descriptor names propagate through the changes feed. Connected card, Manage, picker and QR use the same identity; the chosen folder and descriptor reference are visible. User-selected folders are preserved. Only app-owned nested data folders may follow the notebook name.
- MP3 and compatible audio aliases synchronize. A wrong remote MIME label is corrected only against a matching original and fully verified remote bytes. No file content, ID or history is replaced. Unknown or mismatched files still require attention; independent recordings proceed.
- Complete ZIP export shares the verified recording repair path and identifies unresolved recordings.

## Validation

142 focused protocol/controller checks pass. Synthetic two-device tests cover name propagation and corrected recording download; ZIP round-trip verifies exact audio bytes and no duplicate files. Browser review uses the actual presentation and recording/backup controllers with synthetic services at docs/quality-review/fixtures/drive-identity-review.html. Connected and Manage layouts fit phone/tablet portrait/landscape without horizontal overflow. Physical Google/two-device acceptance remains pending. Owner Drive was read only through locally mounted descriptor metadata; no remote repair, move, rename, deletion or merge was performed during testing. The local descriptors show distinct Drive roots with a shared logical notebook ID; this does not establish which root either physical device uses.

Drive API contract: the binary `mimeType` cannot be changed without a new content revision ([Google reference](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)). The former MIME-only PATCH was invalid for real Drive. This release records the verified type in `appProperties.spinoMimeType`; it never uploads a replacement recording revision. New uploads retain their original known type there. The synthetic Drive now rejects metadata-only MIME updates, and regression tests enforce use of private metadata, full byte verification, unchanged file IDs/content and preservation of other recording properties.
