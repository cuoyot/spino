The owner reports that stable and beta apps on the same tablet select a Drive file but remain waiting or fail to apply a reviewed cloud choice. Two reproducible source defects are corrected:

- Incoming sync used any form in the document as a blocker. Forms retained in closed dialogs therefore blocked adoption indefinitely. Only visible editing forms and open dialogs now block adoption; non-editing library search does not. Pending practices still require finishing/saving to protect progress, and the waiting message explains the real blocker rather than implying a pause is sufficient.
- A cloud/local conflict decision could be lost while incoming data was deferred, reopening the same conflict. The reviewed preference and snapshot hash are retained across eligibility/apply deferral. Resolution is applied once safe; changed local/remote data require fresh review. A reviewed merge is not written remotely while local adoption is blocked. Recovery, stable IDs and compare-and-swap protection remain intact.

The setup screen no longer exposes a separate sibling file-selection action. Stable and beta installations still own separate local databases/provider grants; both must select the same cloud file. A simulated older writer that strips additive QR metadata remains readable and the current client retains/restores the same notebook identity. This does not claim validation against the owner's actual tablet/file.
