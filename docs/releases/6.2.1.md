# SPino 6.2.1

Android versionCode 121. Owner-requested promotion of published beta120 to production, with a new update notice. The owner explicitly requests an immediate 100% rollout (9 November 2026). Google approval and actual public availability must be verified separately.

## Changes

Clearer Calendar, Library, Progress and practice controls; easier catalogue and score selection; more comfortable MusicXML instrument selection, 20–300% zoom and reversible labels/fingering. Existing scores, annotations, record IDs and notebook progress are retained.

An installation-local notice summarizes these improvements after updating. It is dismissible, appears once per release and waits until there is no unfinished practice or higher-priority dialog. New installations keep onboarding instead. The neutral optional rating action opens the existing Google Play listing; it adds no review SDK, rating gate, incentive, telemetry, permission or developer data collection.

## Validation

Validation, signed artifacts, emulator retention, Play acceptance and exact website publication are recorded in the release evidence.

### Test scope and inherited debt

The initial complete suite ran 732 checks: 673 passed, 56 failed and three skipped. The published beta120 baseline independently ran 728 checks: 671 passed, 54 failed and three skipped. All release-only failure names were sparse-checkout artifact paths or the same header-parity case reported under its filename by the baseline. Existing tests still assume superseded Drive setup, planning and practice controls. This is not an all-green full suite. Logs and the exact comparison are retained.

Corrected actual translation/contrast issues and relevant fixture/output-path drift. The final release gate passes 48/49 checks, with one optional external-score case skipped; website checks pass 11/11 and Android checks pass 15/15. Unrelated inherited tests have not been rewritten or disabled.

No new Android permissions, accounts, analytics, advertising SDKs or developer data collection are introduced. The optional rating action reuses the existing store URL. Existing privacy/Data safety declarations are unchanged.

Replacement emulator installation succeeds after recovery of a failed emulator package service. All 135 original IndexedDB files match their pre-install bytes, and the updated activity is foreground. Private recovery archive retained outside version control. This is native package/retention evidence, not physical-device visual acceptance.

## Website download consistency correction

The first direct publication exposed an existing generator behavior: `cp` with `force:false` preserved provisional same-version download parts and checksums while the Worker metadata referenced the final signed packages. Full public download verification rejected the result. The generator now compares and replaces current stable/beta artifacts while retaining historical files. A regression reproduces the mismatch and verifies manifest bytes, each split part and the reconstructed signed artifact hashes against the source. The AAB accepted by Play is unchanged. Initial failed-publication evidence is retained under the attempt1 filenames; final publication proof is separate.
