# SPino 6.1.5-beta.5

Android versionCode 104. Fixes backup setup after creating a folder and renaming the notebook when a Drive ancestor is outside the app's file access. Notebook and object IDs are preserved; retries reuse child folders.

## Validation

54 focused tests pass, including regression through the real incremental notebook adapter. The original code reproduces the reported message; the correction tolerates only missing optional ancestors. Selected-folder, permission, descendant and provider-rejected move failures still prevent activation. No personal Drive resources were modified. Physical Google Drive acceptance remains pending.

ZIP export now shows preparation/save failures in a separate visible result with Retry. Previously transferFeedback closed the dialog and the form catch wrote into its hidden error element, matching the owner's reported silent return. The actual cause of the owner's ZIP preparation failure is still unknown; the corrected UI exposes that error instead of claiming it is fixed. Synthetic controller tests cover preparation failure, retry success and native save rejection.

Closing ZIP progress keeps preparation running. Backup & sync shows a persistent preparation/ready/error card; View progress reopens the same operation without duplicate work. Completed ZIPs remain in memory while Spino is open and expose Choose where to save after the dialog was closed. Save retries reuse the prepared ZIP. A new snapshot requires the explicit Prepare a new copy action. Android's share chooser does not prove the receiver saved a file.
