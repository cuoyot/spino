# SPino 6.1.6-beta.2

Android versionCode 108. Website beta APK updates the existing `com.miguecoll.spino.beta` application, alongside stable 6.1.5 (106).

## Release notes

Sync now checks for changes without rereading the whole notebook when unchanged. Recording checks no longer leave the synchronization icon rotating after their task ends. Waiting messages show the known reason without incorrectly referring to an active practice. Your existing connection and notebook data are preserved.

## Implementation

Routine manual checks share the verified changes cursor with polling and can skip unchanged local asset export. Local edits and concurrent incoming changes still reconcile. Manual retries after errors and conflict resolution retain full inventory. Ineligible recording passes clear only transient checking/copying states; errors, offline policy and explicit pause are retained. Discovery and copying reuse the same permitted media client. Incoming-data guards remain in place, and the Drive panel uses their actual wait reason.

## Validation

115 focused controller/protocol/media/view/coordinator checks and three browser regressions pass before release packaging. The actual browser action produces one changes-feed request and zero local asset exports for an unchanged notebook, then recovers from an overlapping interrupted recording check. Versioned release checks, package/signature verification, replacement-install data retention and public download hashes are recorded separately in the release reports.

The owner's roughly 25-second observation was visible spinner activity, not an instrumented protocol duration. Physical Google Drive timing after this fix remains to be measured. The retained full-suite baseline is not green; this release distinguishes new failures from that baseline.

## Testing

Install over your existing beta without changing the Drive connection. In Backup & sync, tap Sync now with no edits and check that rotation stops. Repeat while recording copies are checked. Check the same notebook on a second device, local edits and offline return. Genuine incoming edits must still wait while practice or an editor is active.
