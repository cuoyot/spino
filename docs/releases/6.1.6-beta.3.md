# SPino 6.1.6-beta.3

Android versionCode 109. Website beta APK updates `com.miguecoll.spino.beta`. Stable 6.1.5 (106) remains available. This includes the manual-check and recording-status corrections prepared in beta.2 (108), which was tagged but not deployed to the website before the terminology follow-up.

## Behavior

Cloud synchronization keeps the connected notebook and selected files usable across devices. A new phone connects the same Google account and opens the existing notebook. Backups are separate compressed ZIP archives, saved or explicitly restored for recovery; synchronization never reads them as live data. JSON export/import stays available as notebook portability, with truthful labels.

Settings are unknown until a complete Drive lookup succeeds for the current account/notebook. Unknown or failed initial reads do not advertise unfinished setup. Previously verified settings survive a transient failure on the same connection. A changed account/notebook invalidates prior settings, and late results cannot configure the new connection. Genuine missing archive settings still offer the optional daily ZIP setup.

Routine manual checks use the changes cursor and skip unchanged local export. Error/conflict retries retain full inventory. Interrupted recording checks clear transient status and reuse the existing permitted media client. Waiting messages identify the actual known blocker.

## Validation and limits

Focused unit and synthetic responsive-browser results, signed package checks and replacement-install data retention are in the versioned validation report. Browser evidence uses disposable notebooks; native emulator evidence does not prove physical Google timing or two-device acceptance. The full-suite baseline has existing failures; reports distinguish them from release regressions. No data migration, original object deletion or new Drive connection is required.
