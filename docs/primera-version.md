# First release candidate

Updated: 2026-09-30. Technical version: **5.0.0 / Android 29**, above the previous **4.0 / 28**. Product name: **SPino: Smart Piano Notebook**; launcher name: **SPino**. This is a candidate for launch testing, not a published production release.

## Implemented scope

The table below records the pre-review candidate. The 2026-10-01 Today and navigation refinement is implemented and tracked in [D-002/D-003](quality-review/decisions.md), with [comparable captures and verification](quality-review/today.md#refinement-evidence). It introduces a dedicated Practice entry, separates Library content from Profile progress and reduces landscape/MIDI chrome. The app suite passed 210 tests with one optional network skip; a scoped Android navigation smoke check passed. Visual acceptance and the full screen review remain open; this is not a release claim.

| Area | Available behaviour |

| Today (Hoy) | Seven-day activity strip, weekly minutes, start/resume, today's pending practices followed by completed cards with feedback, activity/routine quick starts, upcoming events. |
| Preparation | Context, activity, musical target, duration and tempo slider; explicit input without a piano. Advanced hand/rhythm/presentation/passage settings collapse away. Multi-block routines remain editable. Session naming is deferred to saving. |

| Repertoire PDFs | Validated local import; timed manual practice; paused annotation with 1–5 fingering, text, lines, arrows, circles/ovals, rectangles, pen, underline and highlight. Visual tools and colour palette, text editing, erase, undo/redo, automatic local saving and backup/restore. |
| PDF identification | Visible optional PDF picker in Add work. First-page text extraction and bundled local OCR suggest title, composer and numeric tempo for review. | Session review | Optional five-face assessment, editable final title, comments, practised works and next steps. Partial sessions and manual past entries are supported. |

All notebook screens use the original dark palette; scores retain ink-on-paper rendering. Phone/tablet and portrait/landscape layouts use available space, including split windows. Brief context-sensitive orientation advice appears before playing without shifting the live staff. Touch input retains minimum key sizes and pinch/manual zoom controls.

The selected SPino identity appears in the app header, page title, launcher label, adaptive/monochrome Android icons and launch screen. [Brand assets](../assets/brand/README.md) include prepared Play Store graphics. The application ID, IndexedDB name and backup identifiers remain compatible with earlier installations.

Interactive sessions pause when hidden. Foreground repertoire PDFs keep the manual session timer running and provide pause/resume within the viewer. Manual free/repertoire blocks can explicitly keep the timer running when the app is hidden or the screen is off. Unexpected closure restores the last checkpoint paused; it does not count all the time the process was closed. Checkpoints run every five seconds while active and executable.

PDF margin navigation is active only in reading mode: right advances, left returns. Each target is 3.5% of the visible page width with an 18 CSS pixel cap, including when zoomed. Only a brief stationary single-pointer tap qualifies; pointing inside the score, holding, dragging, annotating or pinching never advances it. Buttons remain usable at all zoom levels, and page changes keep the current framing. Opening a score pauses pending downloads to avoid editing a moving edition. Updates preserve annotated old editions and expose the new PDF separately; identical bytes retain annotations and framing.

PDF practice hides app chrome and Android status/navigation bars. The movable floating widget shows time, pause/resume and page controls while running, with annotation and Back available only in pause. Android Back pauses first and leaves on the next press; leaving restores system bars. Browser fullscreen requires support and may require a fresh user gesture through the framing panel. Direct 1–5 stamps simplify fingering. Paused framing controls save zoom/position per PDF and orientation; reset stores full-page fit. Framing is included in local notebook backups without modifying PDF bytes. Standalone score study is treated as paused.

PDF.js and its worker/fonts/decoders are bundled locally and lazy-loaded when a PDF is used. The original PDF stays unchanged; annotations are a validated page-relative layer in IndexedDB and notebook backups. Saving failures keep the editor open and expose retry. Standalone annotated-PDF export is not implemented. Older unannotated backups remain readable. Import limits are 20 MB per PDF; password-protected PDFs require an unlocked copy. The Node prerequisite is now 22.13+ (or 24+).

Tesseract.js 7 and its English/Spanish integer models are bundled too. Header recognition uses at most 1800 pixels of page width and the top 42% of the first page, with a one-minute timeout and an explicit skip action. Title/composer placement and explicit numeric tempo are heuristics, not a score database lookup. Unusual covers, handwriting and poor scans can require manual correction. Printed tempo ranges or values outside the current 30–160 BPM practice range remain visible as text, without clamping. Import PDF now opens the same review form as Add work; neither writes the notebook before Save. Work and attachment use an atomic transaction, with retry after storage failure.

MIDI disconnection pauses the exercise. Continuing manually separates the measured section from subsequent manual practice. Neither unconnected piano practice nor PDFs create accuracy scores. Subjective feedback remains distinct from measured results.

## Initial content

43 local targets: 12 major, 12 natural minor, 12 harmonic minor and seven Dorian scales. Lessons connect an explanation/question, a technical pattern and generated reading. Visible keyboard range constrains the pattern without stripping required accidentals.

The reviewed repertoire examples are [Mutopia 75, Minuet in G](https://www.mutopiaproject.org/cgibin/piece-info.cgi?id=75) and [Mutopia 1612, Minuet in A minor](https://www.mutopiaproject.org/cgibin/piece-info.cgi?id=1612). The catalog preserves the source's attribution and exact edition. Mutopia and the editions state public-domain status. The A-minor piece is described as related tonal application containing alterations, not as a passage restricted to natural minor.

The full English-base v2 package is integrated through its index. Bibliographic records are visible even without an acquired edition, analysis or permission review. All 618 default records initially remain pending. The legacy v1 Chaulieu seed is historical only; no key-to-ordinal mapping is invented. MusicXML/MXL import, analysis and manual rendering are implemented; calibrated difficulty, general MIDI score evaluation and PDF-to-note conversion remain unavailable. See [repertoire integration](repertoire-integration.md) for architecture, operational steps and separate delivery counts.

## Validation and release limits

The repertoire integration passed package validation (13 manifests / 2,080 total records) and **115 application checks**. An explicitly downloaded real 4,745-byte MXL was validated, analyzed, rendered and yielded 20 independently analyzed excerpt proposals. Its rights/suitability and excerpt boundaries remain pending; zero new public pieces were approved. The rebuilt Android APK was installed with data-preserving `adb install -r`; the native diagnostic verified 618 visible records, pending states, collection search, Wi-Fi score transfer, SHA-256 and immersive SVG rendering. Works, assets, annotations and sessions were unchanged; no frontend exceptions occurred. Diagnostic scores stay in ignored artifacts or temporary memory, not the user notebook.

The immersive-PDF follow-up passed **47 targeted checks**: 34 PDF/companion/import browser and annotation checks, plus 13 notebook/download checks. Coverage includes pause-only editing, direct 1–5 stamps, saved framing and failed-save retry, page/orientation changes, phone/tablet widget bounds, gestures, backups and identical-PDF updates. The Android APK compiled, was installed and passed `check-pdf-practice.mjs`: the WebView expanded from 800×1224 to the full 800×1280 display, Back paused before leaving, fingering and framing survived reopening, and system bars returned on exit. The check left notebook data unchanged and reported no frontend exceptions. Native screenshots are `artifacts/emulator/pdf-practice-*.png`. Android's first-use fullscreen coachmark must be dismissed before testing Back; the diagnostic handles that system prompt.

The PDF-identification follow-up passed four header/tempo unit checks and 25 browser checks covering the import form, actual scanned OCR, cancelled/replaced files, protected manual values, atomic-save retry, the existing PDF editor and companion practice. Native verification in the installed Android APK recognized title/composer and 96 BPM from a JPEG-only PDF and 88 BPM from PDF text, while leaving works and assets unchanged. The Android model-packaging issue was fixed by shipping uncompressed `.traineddata` filenames. Screenshots are `artifacts/emulator/add-work-pdf.png` and `add-work-ocr.png`. Verbal tempo directions are retained as text without inferred BPM; printed pulse symbols always remain subject to review.

The full automated run on 2026-09-30 passed **83 tests**, covering session time/pauses, feedback and older data, date/DST handling, backup validation/restoration, scale constraints, browser workflows, simulated MIDI loss, tempo, touch gestures, multiple viewport sizes, network policy and download replacement failures. Today/calendar/planner checks cover feedback, two-week agendas, moved/completed plans, dated Add actions, tutor classes, existing dates, repeated submission and routine preservation. PDF checks cover import rejection, every drawing tool, text escaping, undo/redo/erase, separate page marks, rotated PDFs, narrow-margin gestures, cancelled touches, pinch zoom, responsive layout, storage failures, retained editions and backup validation. The final nine-check PDF browser suite also verified restoration of actual annotated backups and refreshed practice controls after leaving the viewer. The common preparation flow keeps its start action visible in the tested 320×568, 360×640, 390×844, 844×390, 768×1024 and 1180×820 viewports. The final web build and Android debug APK compiled successfully and were installed/reopened in the existing emulator. The native smoke check verified Today navigation, fourteen day rows and the weekly assistant preview without adding test appointments. It confirmed unmetered Wi-Fi, downloaded a real 180,708-byte Mutopia PDF with four progress events and rendered it in the full-screen shared editor. It then verified Android Back, advanced a two-page fixture through a narrow margin tap and drew a page-specific annotation using touch input. Test marks stayed in memory and no notebook assets or practices were created. The final run reported no frontend exceptions. Notification permission was read without changing it or replacing reminder schedules. Production dependency audit reported no known advisories.

Browser backup tests cover attachments and history. Native system file pickers, reminder delivery with the app closed and physical USB/BLE instruments still require a device acceptance pass. Simulation does not substitute for physical MIDI testing. Wi-Fi-to-cellular transitions also need a real dual-network device check.

The score-guide alignment correction passed 14 relevant browser checks, including phone/tablet orientations, both score presentations, later systems, tempo stability and page navigation. Cursor/light bounds now come from the rendered SVG staves; whole-note heads share the same beat centres as other durations. Independent guide transitions were removed so a layout change cannot temporarily separate the guides from the music. The rebuilt APK passed 12 Android WebView cases across treble, bass and grand staff, page/scroll presentation, and quarter/whole notes. Saved preferences/results were unchanged by the diagnostic; screenshots are under `artifacts/emulator/alignment-*.png`.

`SPino.apk` is signed for development. Publication needs the owner's production signing configuration and completed store listing. No release key has been created and nothing has been published.

The existing notebook UI is Spanish and the new repertoire UI uses English as its base language; documentation and source comments are English. The weekly assistant supports a single week or weekly series lasting 4, 8, 12, 26 or 52 weeks. Practices and tutor classes have separate series IDs. Each occurrence can be edited or removed separately; cancelling from an occurrence removes only pending appointments from that date onward, preserving past dates, completed practice and the active session. Dates are materialized locally and included in backups; there is no external calendar synchronisation or indefinite extension; goal-based programmes for auditions, repertoire or passages remain future work. Library distribution is through app updates; no remote catalog backend exists. Optional automatic backup uses user-selected system file providers, with a choice of independent backups or shared notebooks that merge changes and ask about conflicting values; see [cloud backup](cloud-backup.md). There is no SPino account, analytics or server-delivered notification service. The initial iOS backup target still requires Xcode compilation and physical provider acceptance checks.


Planned practice editing now reuses the structured preparation screen: apply a routine, add/remove/reorder blocks and change exercises, duration, tempo or repertoire, then review date/time/reminders before saving. Calendar week rows and month cells accept drops from a dedicated touch/mouse grip; keyboard left/right moves one day. A move updates only the pending occurrence, preserving its ID, blocks, time and series. Active/completed practice is protected; failed writes leave the previous appointment unchanged.

Learning is deferred: its screen, Today lesson card and new-practice activity option are hidden. Existing theory blocks, history and backups remain compatible; scale and mode selection in reading/technique remains available.
